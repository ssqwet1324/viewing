# Формат выходного HTML (v1)

Единственный источник правды для Go-генератора и TS-вьюера. Меняем формат – сначала правим этот файл.

## HTML

```html
<div id="boot">Загрузка…</div>
<script type="application/gzip" id="dv-scene">BASE64</script>
<script type="application/gzip" id="dv-volume">BASE64</script>   <!-- этап 2 -->
<script type="application/gzip" id="dv-viewer">BASE64</script>
<script>/* загрузчик: gunzip(dv-viewer) → <script src=blob:...> */</script>
```

- Каждый блоб – `base64(gzip(bytes))`, base64 стандартный, без переносов строк.
- Загрузчик распаковывает только вьюер. Вьюер сам находит `dv-scene` / `dv-volume` по id.
- Распаковка – `DecompressionStream('gzip')`, других зависимостей нет.
- Title страницы берётся только из конфига. Ничего из DICOM (PatientName и т.п.) в HTML не попадает.

## Контейнер

| смещение | размер | что |
|---|---|---|
| 0 | 4 | magic: `DVSC` – сцена, `DVVL` – объём |
| 4 | 4 | uint32 LE – версия формата блоба |
| 8 | 4 | uint32 LE – `hdrLen`, длина JSON-заголовка в байтах |
| 12 | hdrLen | JSON (UTF-8), дополненный пробелами справа |
| 12+hdrLen | … | тело до конца файла |

**Отличие от референса:** `12 + hdrLen` всегда кратно 8. Тогда JS делает `new Uint16Array(buf, off, n)` /
`Float32Array` прямо поверх распакованного буфера, без копирования (типизированным массивам нужно
выравнивание по размеру элемента). JSON.parse пробелы в конце игнорирует.

## Сцена (`DVSC`, версия 1)

```jsonc
{
  "title": "Пациент 001",
  "units": "mm",
  "meshes": [
    {
      "id": "bone",              // уникальный, [a-z0-9_-]
      "name": "Кость",           // для UI
      "kind": "bone",            // anatomy | bone | implant | abutment | sleeve | waxup
      "color": "#e3dccf",        // sRGB
      "opacity": 0.7,            // 0..1
      "visible": true,
      "shading": "smooth",       // smooth | flat | crease
      "crease_deg": 30,          // только для crease
      "transform": [16 чисел],   // row-major 4×4, необязателен (нет = единичная)
      "geom": 0                  // индекс в geoms; несколько мешей могут ссылаться на один geom
    }
  ],
  "geoms": [
    {
      "origin": [x, y, z],       // мм, min угол bbox
      "scale":  [sx, sy, sz],    // мм на единицу кванта, по каждой оси своя
      "vertices": 1234,
      "triangles": 2400,
      "index": "u16",            // u16 если vertices <= 65536, иначе u32
      "pos_off": 0,  "pos_len": 7404,   // байты от начала тела, pos_off % 4 == 0
      "idx_off": 7404, "idx_len": 14400 // idx_off % 4 == 0
    }
  ]
}
```

Тело: для каждого geom:
- `positions` – `vertices*3` × uint16 LE, xyz подряд. Координата = `origin[a] + q * scale[a]`.
- `indices` – `triangles*3` × uint16/uint32 LE, обход против часовой (как в STL).
- Между секциями нули до выравнивания на 4.

**Отличия от референса:**
- `scale` задаётся по каждой оси. Для тонкого длинного импланта это даёт точность выше на порядок,
  а стоит три числа вместо одного.
- Нормали не храним, вьюер считает их сам. Для `crease` вершины расщепляются по углу между гранями.
  Так острые грани имплантов остаются острыми, и при этом не нужно отказываться от дедупа (v = 3·t).

Ошибка квантования ≤ `scale/2` по каждой оси. При bbox 80 мм это ≈ 0.6 мкм.

## Система координат

Мм, Z вверх (краниально), −Y – вперёд (антериорно), +X – влево пациента (как DICOM LPS).
Для Real Guide это предположение, проверим на этапе 2 по совпадению кости из STL с изоповерхностью КТ.
